## 2. Phase B：PLATEAU静的GISの投入（仕様書§7-2、タイムボックス10営業日）

成功条件（仕様書§10-3、§11）：小範囲のLOD1建物を`SpaceInfra-cpp`経由で変換・登録・照会できること。

**2026年8月6日時点で建物・道路・土砂災害・洪水浸水・土地利用を部分達成。地形のみ未実施。`SpaceInfra-cpp`は使用不可と判断し、§10-3の代替案（自前ボクセル化）を実行した。詳細は仕様書v0.8・[進捗ログ.md](進捗ログ.md)の該当日エントリを参照。**

- [x] 2-1. 秩父市PLATEAU 2025の索引図から対象の1三次メッシュ相当を選定する（仕様書§5-1、§12「対象メッシュ」）。**3次メッシュ`53397062`を選定**（索引図との厳密な照合ではなく、実ファイルサイズから建物が一定数あるメッシュを選択）。
- [x] 2-2. 対象データセットの建物・地形・洪水浸水・土砂災害・土地利用・道路の各レイヤを取得する（仕様書§7-2手順2）。**建物・道路・土砂災害・洪水浸水・土地利用は取得済み**。土地利用（`udx/luse`、対象2次メッシュ`533970`、約19MB・圧縮後約3.4MB）はHTTP Rangeで全体取得後、既定航路周辺±0.008度で5302件中99件に絞り込んだ。地形（`udx/dem`は1ファイル300〜500MBで対象外と判断）のみ未取得。
- [x] 2-3. 建物・地形が`SpaceInfra-cpp`で変換可能か検証する（仕様書§7-2手順3、§12「変換経路」）。**検証結果：不可**（Windows専用VSプロジェクト、Renderで実行不可。加えて登録API自体が存在しないことも判明）。§10-3の代替案（自前ボクセル化）へ移行。
- [x] 2-4. 変換結果を地物ボクセルとして登録する（仕様書§7-2手順3）。**建物29件・道路30件・土砂災害13件・洪水浸水20件・土地利用99件を`ground_feature_objects`へ直接登録**（`plateau:import-buildings`／`plateau:import-features`Artisanコマンド、junhongo-ccs/airway-digitaltwin-db）。`object_cd`は1=建物・2=道路・3=土砂災害・4=洪水浸水・5=土地利用という本PoC独自の割り当て。地形は未実施。**追記（2026年8月7日）**：投入時は高さ（measuredHeight）のみクライアント側JSON（`plateau_building_heights.json`）に保存し、フットプリント（`lod0RoofEdge`）は保存していなかった。同じ3次メッシュ`53397062`の建物ファイルをHTTP Rangeで再取得し、29件全件のフットプリントを`plateau_building_footprints.json`として追加保存、地図描画に対応した（§7-3手順4）。
- [x] 2-5. 洪水浸水・土砂災害・土地利用・道路を、エリアまたは汎用オブジェクトとして登録する（仕様書§7-2手順4）。国土数値情報との二重登録を避ける（仕様書§5-1）。**全レイヤ登録済み**（2-4と同じ経路。`area`／`general_purpose`経由ではなく`ground_feature_objects`への直接登録とした。理由はarea経由だとPhase Aで判明したネイティブ変換処理依存の問題を再度踏むため）。
- [x] 2-6. 航路周辺の地物・エリアをAPIで取得できることを確認する（仕様書§7-2手順5）。**建物・土砂災害・土地利用はRenderで取得確認済み**（`GET /ground_feature_voxel`）。土地利用は既定航路周辺±0.008度で絞り込んで投入したため一致した。道路・洪水浸水は登録済みだが、既定航路の位置（空間ID）にたまたま一致するデータが無く未確認。同APIが空間IDの完全一致検索のみで周辺検索ができないための制約（バグではない）。
- [x] 2-7. データセット・出典・変換履歴をDBまたは付属メタデータに保存する（仕様書§7-2手順6、§5-2）。**`data_sources`テーブルへレイヤごとに登録済み**（データセット名・出典URL・取得日・EPSG:6697）。個々の地物の詳細は`update_memo`に記録。
- [x] 2-8. 高度基準統一の前提条件を進める（仕様書§5-3）。各データの水平・鉛直座標参照系、単位、時点を記録し、既知地点でPLATEAU・DEM・ボクセルの高度を比較して許容差を定義する。**建物レイヤに限り達成（2026年8月6日）**：PLATEAU建物はEPSG:6697（JGD2011標高）で、AGLとmeasuredHeightがともに地盤面基準の相対高さのため変換不要と判断。LOD0フットプリントz座標が全件0固定で実測許容差を算出できなかったため、暫定許容差±2mを採用（`viewer/src/altitude.py`）。建物以外のレイヤは高さ情報が無いため引き続き「未検証」。design.md §9-2は「建物のみ検証済み・他は未検証」の表示に更新した。
- [ ] 2-9. ライセンス・帰属表示の棚卸しを行う（仕様書§9-1）。`airway-digitaltwin-db`のApache 2.0 LICENSE／NOTICE、`SpaceInfra-cpp`等同梱ライブラリのライセンス、PLATEAU・国土地理院・国土数値情報のデータ出典表示を配備物に含める準備をする。
- [x] 2-10. 本物の飛行禁止エリアを投入する（仕様書§7-2-補、新設）。**150m高度制限（③）とDID地区（①、国土数値情報A16-2020、秩父市）を実装（2026年8月6日）**。日立の`airspace-digitaltwin-weather-and-prohibitedarea`（DIPS＋MQTT）は使わず、`digitaltwin:import-flight-prohibited-area`Artisanコマンドで直接DB投入する方式を採用。空港周辺（②）は国土数値情報に制限表面データが無く、秩父市周辺に大空港も無いため対象外。DID地区は既定航路と約3km離れているため、確認には始点座標を緯度35.998778・経度139.083660付近に変更する必要がある。

## 3. Phase C：Viewer（仕様書§7-3、タイムボックス5営業日）

成功条件（仕様書§10-3）：APIから航路・空域レイヤを取得し、接続状態・PoC識別・地図・結果を表示できること。0章で作った骨格に機能を組み込む。

**2026年8月6日、実装がStreamlit（`viewer/`）からReact＋TypeScript＋FastAPI BFF
（`viewer-react/`＋`viewer_api/`）へ移行した。以下のチェックボックスはStreamlit版策定時の
ものだが、判定ロジック（`viewer/src/altitude.py`）はBFFがモジュールとして共有利用しており、
チェック項目自体は両実装に共通する。各項目にReact＋BFF版の実績を注記する。詳細は仕様書
§7-3・[進捗ログ.md](進捗ログ.md)の2026-08-06（続き・その4）・2026-08-07エントリを参照。**

### 3-1. 状態表示

- [ ] 3-1-1. API接続状態表示を実装する（design.md §9-1、仕様書§8）。Connected／Disconnected／Errorを色と文字列の両方で表示する。
- [ ] 3-1-2. 対象空間ID／ボクセル解像度の表示を実装する（design.md §9-1）。ユーザー入力ではなく、始点・終点・AGLから算出して表示する。
- [ ] 3-1-3. 評価状態（高度基準）表示を実装する（design.md §9-2、仕様書§5-3、受入基準#9）。「未検証」の間は垂直方向の交差・離隔判定欄を空欄にせず、明示的に未検証と表示する。
- [ ] 3-1-4. PoCデータ識別表示を実装する（design.md §9-3、仕様書§6-1）。画面右上バッジ、テーブルの区分列、地図オブジェクトの破線輪郭の3箇所。

### 3-2. 入力・登録

- [ ] 3-2-1. 入力フォームを実装する（design.md §10、仕様書§7-3手順1）。API接続先、始点・終点、AGL、対象レイヤ。入力欄高さ32px、項目間隔8px。

- [ ] 3-2-3. 航路周辺の地物ボクセル・エリア・注意区域取得のAPI連携を実装する（仕様書§7-3手順3）。**React＋BFF版で地物ボクセルのみ実績あり**（`POST /query_features`）。2026年8月7日、始点のみでbboxを作り常に0件になっていたバグを修正（始点・終点の両方から作成）。エリア・注意区域の取得はBFFに未実装。

### 3-3. 地図

- [ ] 3-3-1. 初期表示レイヤ（地理院地図・航路・建物・注意区域）とON/OFF制御を実装する（design.md §8-1、仕様書§7-3手順4）。**React＋BFF版で部分実績あり**：航路（MapLibre GL）と建物（Phase B投入分29件のみ、2026年8月7日にフットプリント再抽出・描画対応）。地理院地図の背景タイルは未対応（現状OSMタイル）、注意区域は未対応。

- [ ] 3-3-4. 航路と地物／注意区域の交差・取得不能・属性不足を「要確認」として表示するロジックを実装する（仕様書§7-3手順5、design.md §10-1）。**React＋BFF版で部分実績あり**（2026年8月7日）：BFFが`viewer/src/altitude.py`の判定関数（150m AGL・建物垂直・水平bbox重なり）を呼び出し、地物ごとの交差判定を返す。DID地区・注意区域は未実装。
