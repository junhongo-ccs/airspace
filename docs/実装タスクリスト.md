## 0. 事前準備（API非依存・並行可）

design.mdのうちAPI接続を前提としない基盤部分。Phase Aと並行して着手できる。

- [ ] 0-1. カラートークンをCSS変数として実装する（design.md §5-1〜§5-4）。ブランドカラーは暫定HEXのため、正式値が出た時点で§5-1の表のみ差し替えれば波及するように変数化する。
- [ ] 0-2. コントラスト要件をLintまたはチェックリスト化する（design.md §5-5）。特に `--brand-yellow`／`--brand-cyan` を文字色に使わない制約を確認できるようにする。
- [ ] 0-3. タイポグラフィ（フォント指定・サイズ階層・等幅適用ルール）を実装する（design.md §6）。座標・空間ID・ボクセルID・API応答・JSON表示に等幅フォントを適用する。
- [ ] 0-4. グリッド／スペーシングのCSS基盤を実装する（design.md §3）。4px／8px単位のスペーシングトークンを用意する。
- [ ] 0-5. レイアウト骨格を実装する（design.md §4-1、§4-2）。左設定パネル（320px）／地図／登録・照会結果エリア／交差・詳細表・ダウンロードエリア／固定フッターの5ブロックを、中身が空のまま配置する。
- [ ] 0-6. 解像度別の最小寸法・既定折りたたみ状態を実装する（design.md §4-3、§4-4）。1920×1080と1366×768で地図の最小幅・最小高さを満たすか確認する。1366×768ではドロワー方式で結果エリアを重ねる。
- [ ] 0-7. Streamlit実装差異の吸収方針を確認する（design.md §14）。`st.sidebar`幅、入力欄高さ、`st.dataframe`行高、固定フッターの代替手段（CSS注入 or サイドバー最下部＋バナー）を先に検証し、後続タスクの前提とする。
- [ ] 0-8. 免責表示の固定フッターを実装する（design.md §9-4、仕様書§2-2）。**文言は本タスクリストにもdesign.mdにも記載しない。仕様書§2-2の文字列をそのまま参照・表示する実装とする（二重管理禁止）。** Streamlitで固定フッターが困難な場合の代替（§14）も含めて実装する。

**2026年8月6日時点でPhase Aの主要項目は達成。詳細は[進捗ログ.md](進捗ログ.md)の2026-08-05・2026-08-06エントリを参照。**

- [x] 1-8. 各エンドポイントの必須パラメータ・認証要否・レスポンス形式を実機で確定し、記録する（仕様書§6-2）。
- [x] 1-9. Sanctum認証グループがコメントアウトされている件を記録し、外部公開前に必要な認証・ネットワーク制限方針を決める（仕様書§9、§14）。簡易APIキー認証（`VerifyApiKey`）＋Render Private Service化で対応。

## 2. Phase B：PLATEAU静的GISの投入（仕様書§7-2、タイムボックス10営業日）

## 3. Phase C：Streamlit Viewer（仕様書§7-3、タイムボックス5営業日）

成功条件（仕様書§10-3）：StreamlitがAPIから航路・空域レイヤを取得し、接続状態・PoC識別・地図・結果を表示できること。0章で作った骨格に機能を組み込む。

### 3-1. 状態表示

- [ ] 3-1-1. API接続状態表示を実装する（design.md §9-1、仕様書§8）。Connected／Disconnected／Errorを色と文字列の両方で表示する。
- [ ] 3-1-2. 対象空間ID／ボクセル解像度の表示を実装する（design.md §9-1）。ユーザー入力ではなく、始点・終点・AGLから算出して表示する。
- [ ] 3-1-3. 評価状態（高度基準）表示を実装する（design.md §9-2、仕様書§5-3、受入基準#9）。「未検証」の間は垂直方向の交差・離隔判定欄を空欄にせず、明示的に未検証と表示する。
- [ ] 3-1-4. PoCデータ識別表示を実装する（design.md §9-3、仕様書§6-1）。画面右上バッジ、テーブルの区分列、地図オブジェクトの破線輪郭の3箇所。

### 3-2. 入力・登録

- [ ] 3-2-1. 入力フォームを実装する（design.md §10、仕様書§7-3手順1）。API接続先、始点・終点、AGL、対象レイヤ。入力欄高さ32px、項目間隔8px。
- [ ] 3-2-2. 航路登録・取得のAPI連携を実装する（仕様書§7-3手順2）。登録前に対象件数・対象レイヤを、登録後に結果件数とAPI応答時刻を明示する（design.md §10）。
- [ ] 3-2-3. 航路周辺の地物ボクセル・エリア・注意区域取得のAPI連携を実装する（仕様書§7-3手順3）。

### 3-3. 地図

- [ ] 3-3-1. 初期表示レイヤ（地理院地図・航路・建物・注意区域）とON/OFF制御を実装する（design.md §8-1、仕様書§7-3手順4）。
- [ ] 3-3-2. 地図レイヤの色・塗りパターンを実装する（design.md §5-3）。航路／注意区域／禁止区域／建物／地形／情報不足の各トークンと、黄・橙・赤の塗りパターン区別（斜線・交差ハッチ・点ハッチ）を適用する。`--brand-future-blue`は地図オブジェクトに使わない。
- [ ] 3-3-3. 地図上の常設UI（凡例・スケールバー・座標／空間ID表示帯・北矢印）を実装する（design.md §8-2）。レイヤ制御は地図上に重ねず左設定パネル内に置く。
- [ ] 3-3-4. 航路と地物／注意区域の交差・取得不能・属性不足を「要確認」として表示するロジックを実装する（仕様書§7-3手順5、design.md §10-1）。

### 3-4. テーブルと結果表示

- [ ] 3-4-1. 結果テーブルを実装する（design.md §7）。行高32px、セル余白上下左右8px、数値右寄せ・等幅、状態・区分中央寄せ、ヘッダ固定。
- [ ] 3-4-2. 必須列を実装する（design.md §7-1）。取得日時、データ出典、API種別またはレイヤ種別、区分（PoC／実データ）、座標参照系または高度基準（高度を含む行）。
- [ ] 3-4-3. 空状態・エラー・処理中の表示を実装する（design.md §10-1）。該当0件、取得失敗（HTTPステータス・エンドポイント・再試行ボタン）、属性不足バッジ、未登録時の導線、処理中の進捗表示。

### 3-5. 出力

- [ ] 3-5-1. 「登録・照会結果」エリアを実装する（design.md §4-1、仕様書§8）。API応答・件数・データ時点を表示し、独立して折りたたみ可能とする。
- [ ] 3-5-2. 「交差・詳細表／ダウンロード」エリアを実装する（design.md §4-1、仕様書§8）。交差・情報不足の詳細表を表示し、独立して折りたたみ可能とする。
- [ ] 3-5-3. CSV／GeoJSON出力を実装する（仕様書§7-3手順6、§8）。入力値、照会日時、データ出典、結果を含める。免責文言（仕様書§2-2）を出力にも同一文字列で含める（design.md §9-4）。

### 3-6. アクセシビリティ・仕上げ

- [ ] 3-6-1. キーボード操作とTab順を実装する（design.md §12）。左設定パネル→地図→結果エリア（登録・照会結果→交差・詳細表）→フッターの順。
- [ ] 3-6-2. フォーカスリング（内側1px白＋外側2px `--focus-ring`）を実装する（design.md §12）。
- [ ] 3-6-3. ショートカットキー（照会：Ctrl+Enter、レイヤパネル開閉：Ctrl+L、凡例開閉：Ctrl+G）を実装する（design.md §12）。実装時に割り当てを最終確定する。
- [ ] 3-6-4. 200%拡大表示での操作性を確認する（design.md §12）。この場合は地図の最小寸法要件を適用しない。
- [ ] 3-6-5. カード・アイコンの使用範囲を確認する（design.md §13）。カードは設定パネル／API状態表示／評価状態表示のみ。アイコンは接続状態・評価状態・ダウンロード・レイヤ表示・警告のみで、必ずラベルまたはツールチップを併記する。
