# 実装進捗ログ

このドキュメントは日付ごとに記録を追記していく形式。**新しい作業をした日は、既存の内容を
書き換えず、このファイルの最新エントリの直後（＝ファイル先頭寄り）に新しい`## YYYY-MM-DD`
節を追加する。** 過去の記録は消さない。最新の日付が一番上に来る、新しい順の並びとする。

各日のエントリには次の3つを書く。

- **実施内容**：その日にやったこと（コード変更・調査・デプロイ操作など）
- **既知の問題・未解決事項**：解決しなかったこと、判明した制約
- **次回タスク**：次にやるべきこと

8. **実APIの契約調査と対応**（すべて実コード確認済み）：
   - `GET /drone_route`は一覧取得ではなく`drone_route_id`必須の単体取得。`POST /drone_route`は`drone_route_id`（クライアント採番）・`coordinates`・`from_datetime`（`Y-m-d H:i:s`厳密一致）が必須で、成功時は本文が空。
   - `GET /ground_feature_voxel`は`bbox`ではなく`other.typeCd`・`identification`・`timing`が必須。レスポンスは緯度経度ポリゴンを含まず、ボクセルビット参照のみ（地図描画は現状不可）。
   - `GET /general_purpose`（area・flightProhibitedArea等の汎用エンドポイント）は`identification`・`timing`・`requestType`・（areaの場合）`other[timingTo]`が必須。
   - `ApiFunction::get_spatial_xy_on_point`から空間IDの実仕様（ズーム17固定・Web Mercatorタイル形式`"z/0/x/y"`）を確認し、プレースホルダのSHA1ハッシュから実装を差し替え（`src/spatial_id.py`）。
   - `area`・`flight_prohibited_area`の登録は外部ネイティブ実行ファイル（`popen('start /B ...')`、SpaceInfra-cpp相当）を呼び出して空間ID紐付けテーブルを作る設計だが、そのexeは本デプロイに含まれないため、**登録は成功しても一覧取得は空のままになる可能性が高いことが判明**。
