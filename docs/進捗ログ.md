# 実装進捗ログ

このドキュメントは日付ごとに記録を追記していく形式。**新しい作業をした日は、既存の内容を
書き換えず、このファイルの最新エントリの直後（＝ファイル先頭寄り）に新しい`## YYYY-MM-DD`
節を追加する。** 過去の記録は消さない。最新の日付が一番上に来る、新しい順の並びとする。

各日のエントリには次の3つを書く。

- **実施内容**：その日にやったこと（コード変更・調査・デプロイ操作など）
- **既知の問題・未解決事項**：解決しなかったこと、判明した制約
- **次回タスク**：次にやるべきこと

7. **フックのコマンド文字列で`$`を使い、SessionStartフックを壊した（同セッション内で発見・修正）**：
   「サブディレクトリから`claude`を起動するとフックの相対パスが解決できない」ことを懸念して、
   `.claude/settings.json`のコマンドを
   `pwsh ... -Command "& (Join-Path ($env:CLAUDE_PROJECT_DIR ?? $PWD) '.claude/hooks/...')"`
   の形に変更したところ、起動時に
   `:CLAUDE_PROJECT_DIR: The term ':CLAUDE_PROJECT_DIR' is not recognized...` で失敗した。
   **Windows環境でもフックのコマンド文字列はGit Bash経由で実行されるため、pwshに渡る前に
   bashが`$env:...`・`$PWD`を展開してしまう**のが原因（`$env`が消えて`:CLAUDE_PROJECT_DIR`
   だけが残る）。`bash -c '...'`で再現を確認した。
   - 対処：`-Command`をやめ、`$`を一切含まない
     `pwsh -NoProfile -ExecutionPolicy Bypass -File .claude/hooks/<script>.ps1` の形へ戻した。
     修正後、`bash -c`（＝フックと同じ実行経路）でSessionStart・Stopの両方が正常動作すること
     を確認した。
   - **教訓：フックのコマンド文字列には`$`を書かない。**環境変数やパス解決が必要な処理は、
     コマンド行ではなくスクリプト側（`$PSScriptRoot`基準）で行う。本フックのスクリプトは
     元から`$PSScriptRoot`からリポジトリルートを求めているため、`-File`の相対パスさえ解決
     できれば正しく動く。

     （下記「既知の問題」参照）。
