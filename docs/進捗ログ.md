1. **StreamlitからReactへの全面移行を決定した**：

     design.mdのデザイントークンはそのまま流用する。

2. **BFF（Backend for Frontend）パターンを採用し、独立サービスとして分離した**：
   - ユーザーから「backendを別のサービスにデプロイしたほうがいいのではないか」という
     指摘があり、Laravel APIをReactへ直接公開するとCORSと認証情報露出の問題が出るため、
     間にBFFを挟む構成に決めた。当初はStreamlitと同居させたが（`viewer/api.py` +
     `entrypoint.sh`）、**fastapi/uvicorn/starlette/anyioとstreamlitの依存が解決不能**
     （streamlit 1.61.0は`starlette>=0.46.0`、当時のfastapiは`starlette<0.39.0`を要求）
     だったため、独立したWeb Service `airspace-viewer-api`（`viewer_api/`）へ分離した。
     これで各サービスが必要な依存だけを持てるようになった。最終構成:

         React (airspace-viewer-react, 公開)
           -> FastAPI BFF (airspace-viewer-api, 公開)
             -> Laravel (airspace-drone-web, Private Service)

3. **`DigitalTwinApiClient`からStreamlit依存を除去した**（コミット`1c37d41`）：
   - BFFが存在しないモジュールレベル関数（`register_route`等）をimportしており、
     FastAPI起動時点で`ModuleNotFoundError`になっていた。実体は
     `viewer/src/api_client.py`の`DigitalTwinApiClient`クラスのみ。
   - さらに同クラスは`st.session_state`を直接触っており、Streamlitが無いプロセスでは
     動かなかった。**状態辞書を`state`引数で注入する形**に変更し、Streamlitは
     `st.session_state`を渡し、BFFは省略（またはプロセス内辞書）で動くようにした。
     クラス抽出ではなく依存性注入にしたのは、Laravel通信ロジックの重複を作らないため。
   - レスポンスの航路識別子を`id`に統一（React側も`route.id`を読む）。

4. **「モックなのに実API接続済みに見える」問題を潰した**（コミット`c812529`）：
   - `DIGITAL_TWIN_HOST`の有無だけでmockを決めていたため、`DIGITAL_TWIN_BASE_URL`を
     指定しても黙ってmockへ落ち、疎通試験にならなかった。`MOCK_MODE`を明示フラグとして
     追加し、未設定時のみ接続先設定から推測する。render.yamlでは`MOCK_MODE=false`を明示。
   - `/connection_status`が`mock`と`base_url`も返すようにし、画面でも「モックモード」を
     「接続済み」とは別扱い（黄色）で表示する。今回の疎通検証で最も効いた改善。

5. **失敗を成功として表示していた箇所を修正した**（コミット`c812529`）：
