# 左ペイン結果オーバーレイ改善計画

作成日：2026年9月7日  
状態：実装計画・UI検証待ち  
対象：React Viewer（`viewer-react/`）  
優先度：次回UI改善

## 1. この文書の位置付け

React Viewer の航路照会画面について、入力・待機・結果・再入力の操作を左ペインだけで完結させるための実装計画である。次にこのUIを変更する人またはエージェントは、実装前に本書、`docs/design.md`、および対象コンポーネントを読むこと。

`docs/design.md` §4 は従来の「左設定パネル・地図・下部結果エリア」構成を記録している。本書は、**React版における結果表示の配置と状態遷移について、その従来方針を置き換える決定**である。Streamlit版のレイアウト変更を意味しない。React実装とUI確認が完了した段階で、`design.md` 側の恒久仕様も本書と矛盾しないよう更新する。

## 2. 背景と目的

現行のReact Viewerでは、利用者が左ペインで始点・終点・AGL・レイヤを設定し、「航路を登録して周辺データを照会」を押す。照会結果と判定詳細は地図の下部にある `ResultsPanel` に表示される。

下部から出現する結果パネルは、地図の主表示領域を分断し、入力・照会・結果確認という一連の作業を視線移動の大きいものにする。改善後は、地図を常に主役として残し、操作と判断に必要な情報を同じ左ペイン内で切り替える。

## 3. 決定事項

### 3-1. 左ペインは三状態を持つ

左ペインの幅は現行どおり 320px（許容範囲 300〜340px）とする。同じ領域で、次のビューを切り替える。

| 状態 | 表示 | 入力フォーム | 地図 |
|---|---|---|---|
| 入力 | 接続状態、航路入力、AGL、レイヤ、照会操作 | 操作可能 | 常時表示 |
| 待機 | 結果オーバーレイ内の処理状況 | 非表示・操作不可 | 常時表示。既存の地図側待機表示があれば併存可 |
| 結果 | 結果サマリー、判定詳細、再入力操作 | 非表示・操作不可 | 常時表示 |

待機と結果は、入力ビューの上に置かれる不透明な左ペイン内オーバーレイである。画面全体、地図、画面下部を覆うものではない。

### 3-2. 縦方向にせり上がるアニメーションは採用しない

照会ボタンを押した直後、左ペインは素早くせり上がる・せり下がる動きをせず、**その場で待機状態へ移行する**。待機表示から結果詳細への切替も同じ位置で行う。

- 下部から出るパネル、ボトムシート、画面全体を覆うモーダルは使わない。
- 結果ビューの表示・再入力への復帰に必要なら、短い不透明度の変化だけを許容する。縦方向の移動は行わない。
- OS の `prefers-reduced-motion` を尊重し、動きを完全に省略できるようにする。

### 3-3. 待機状態は空白にしない

照会開始時点で結果オーバーレイを表示し、空の結果領域を出さない。オーバーレイ中央付近に小さな回転インジケーターを置き、既存の色・文字トークンを使って現在の処理を示す。

表示する内容は次のとおり。

1. 現在の主状態（例：`航路を登録しています`、`周辺データを照会しています`）
2. 段階表示
   1. 航路を登録
   2. 周辺地物を照会
   3. 飛行禁止区域を照会
3. 実装可能な範囲での経過時間、対象レイヤ、対象件数

段階の完了を実際に観測できない場合、完了済みであるように誤認させる表示はしない。まずは「現在実行している処理」を正確に示し、APIから進捗を得られる場合だけ段階完了表示へ拡張する。「結果を整理」のような、非同期の待ちを伴わない同期処理は独立した段階として表示しない。直後に結果ビューへ切り替わるため、実装上その段階が描画される機会がなく、表示と実装が食い違う（レビュー指摘2026-09-07）。

### 3-4. 結果ビューと再入力

結果が得られたら、同じオーバーレイ内で待機表示を結果表示へ置き換える。結果ビューは次の順序とする。

1. 結果状態（成功・一部成功・失敗）
2. 航路ID、取得時刻、データ出典、周辺状況の要約
3. 判定詳細のアコーディオン
   - 航路への影響
   - 航路活用の可能性
   - 土地利用
   - 飛行禁止区域
4. 注意・免責・「未確認」表現

「再入力する」操作は、結果オーバーレイ内の**非スクロール領域**に置く。結果詳細が長い場合でもスクロールなしで操作できることを優先する。位置は結果ビューの固定フッターを基本とする。これは画面下部パネルではなく、左ペイン内部の操作領域である。

「再入力する」を押すと入力ビューへ戻る。始点・終点・AGL・レイヤ設定は最後に入力した値を保持し、利用者は微調整して再照会できる。

### 3-5. 地図と結果データは不用意に消さない

再入力へ戻る操作はUIビューを切り替えるだけであり、`queryResult` を `idle` に初期化してはならない。

地図には直前の照会済み航路と結果レイヤを残す。「最後に照会成功した航路」（`confirmedRoute`）と「編集途中の入力値」（`startLat`等）を分け、地図は常に `confirmedRoute` を参照する。`queryResult.status` を直接参照する実装は避ける：再照会のたびに `status` が一時的に `loading` になるため、`queryResult.status` から地図の表示可否を導くと、待機中だけ直前の確定航路が地図から消える（レビュー指摘2026-09-07）。`confirmedRoute` は航路登録（`registerRoute`）が実際に成功した時点でのみ更新し、以降そのクエリが待機・失敗しても値を保持する。

## 4. レイアウトとデザイン制約

- 基準：`docs/design.md` §3 の4pxベースグリッド、8pxレイアウト単位。
- 使用する主な値：4、8、12、16、20、24、32、40、48px。恣意的な端数値を追加しない。
- 左ペイン幅：320px（300〜340px）。結果を表示するために広げない。
- 画面外周16px、パネル内部12px、コンポーネント間8px、セクション間16px、ラベルと入力欄の間4pxを基本とする。
- 現在の有効なTailwindスペーシングを、今回と無関係な箇所まで一括で変更・正規化しない。
- `tailwind.config.js` の既存カラートークン、既存の文字スタイル、既存依存関係を維持する。新しいUIライブラリやCSSフレームワークは導入しない。
- ボタン高は `docs/design.md` §10 に合わせて32〜36pxとする。

## 5. 実装方針

### 5-1. 対象コンポーネント

| 対象 | 役割 |
|---|---|
| `viewer-react/src/App.tsx` | 入力・待機・結果ビューの状態を管理し、既存の `handleQuery` を維持する |
| `viewer-react/src/components/SettingsPanel.tsx` | 入力ビューとして利用する。現状はフォーム全体を不活性化する prop を持たないため、親コンテナ側で操作・フォーカスを抑止する方針を優先する。内部レイアウトは結果オーバーレイと同じ「スクロール領域＋固定フッター」構成にする：座標・AGL・レイヤ設定はスクロール可能な領域に置き、レイヤ設定をその領域の最後（照会ボタンの直前）に配置する。照会ボタンはスクロール領域の外（左ペイン最下部の固定フッター）に置き、レイヤ一覧の長さや画面解像度に関わらず常に到達できるようにする（ユーザー指示2026-09-07。2026-08-18時点の「ボタンをレイヤより上に置く」対応は、ボタンを固定フッター化したことで不要になった） |
| `viewer-react/src/components/ResultsPanel.tsx` と新規 `ResultsOverlay.tsx` | `ResultsPanel` の下部パネル用コンテナは流用せず、左ペイン専用の `ResultsOverlay` を作る。結果サマリー・判定詳細・アコーディオンの内容ロジックは必要に応じて共通部品化して再利用する |
| `viewer-react/src/components/CollapsibleSidebar.tsx` | 現状の `relative` な `aside` と内容側の `overflow-hidden` がオーバーレイ配置に必要な条件を満たすため、変更しない。子要素側の相対配置コンテナでオーバーレイを重ねる |

### 5-2. 状態管理

`showResults: boolean` だけで「待機」「結果」「入力」を曖昧にしない。少なくとも `input`、`loading`、`result` を区別するビュー状態を持つ。

- 照会開始：既存の `handleQuery` の処理を開始し、ビューを `loading` にする。
- 照会完了：成功・一部成功・失敗のいずれでもビューを `result` にする。失敗時には再試行・再入力の導線を表示する。
- 再入力：ビューだけを `input` に戻し、入力値・結果データ・地図の確定表示を保持する。
- `SettingsPanel` の `onQuery` を単なる `setView(...)` で置き換えない。必ず既存の非同期照会処理を呼ぶ。

入力ビューが背後にDOMとして残る場合、視覚的に隠すだけでは不十分である。オーバーレイ表示中はポインタ操作、Tab移動、スクリーンリーダーの到達対象にならないようにする。

現時点の `SettingsPanel` には、この目的の `disabled` prop は存在しない。個々の `input`・`button`・アコーディオンへ `disabled` を伝播させる実装は漏れやすいため、まず入力ビュー全体を包む親コンテナを不活性化する方法（例：`inert` と適切な `aria-hidden`）を検討する。実装後は、結果オーバーレイへフォーカスが移り、背後のフォームへ Tab 移動できないことを確認する。

### 5-3. オーバーレイの配置

左ペインの内容を包む相対配置コンテナ内に、結果オーバーレイを `absolute inset-0` で配置する。

- `position: fixed` は使わない。
- オーバーレイは左ペインのクリップ領域からはみ出さない。
- 背景は既存のパネル背景色で不透明にする。
- 結果詳細だけを縦スクロール可能にし、再入力操作はスクロール領域外に維持する。

`CollapsibleSidebar.tsx` の `aside` はすでに `relative` であり、内部には `overflow-hidden` のクリップ領域がある。したがって `CollapsibleSidebar` にオーバーレイ専用APIを追加する必要はない。`App.tsx` から渡す子要素を `relative h-full` のラッパーにし、その中に `SettingsPanel` と `ResultsOverlay` を兄弟要素として置く構成を基本とする。

## 6. 非対象

- API、BFF、環境変数、データ型、照会ロジック、MapLibreの地図ロジックの変更
- 仕様書上の免責文言や飛行可否判断ロジックの変更
- 新しいUIライブラリ、CSSフレームワーク、デザインシステムの導入
- Streamlit版のレイアウト変更

## 7. 受入条件

- [ ] 照会前は左ペインに入力UIだけが表示され、下部結果パネルは表示されない。
- [ ] 照会開始後、左ペインは空白にならず、同じ位置で待機状態を表示する。
- [ ] 待機状態から結果詳細へ、地図・左ペインがせり上がることなく切り替わる。
- [ ] 結果表示中、背後の入力フォームはマウス・キーボード・支援技術のいずれでも操作できない。
- [ ] 結果表示は左ペイン内で完結し、画面下部パネル、ボトムシート、モーダルを使わない。
- [ ] 「再入力する」は結果詳細の長さにかかわらず、最初の表示領域内で操作できる。
- [ ] 再入力時に始点・終点・AGL・レイヤ設定が残り、微調整して再照会できる。
- [ ] 再入力時に直前の確定航路・地図結果が意図せず消えない。
- [ ] 値を微調整して再照会している間（待機中）も、地図には再照会前の確定航路が表示され続け、新しい航路登録が成功した時点でだけ切り替わる。
- [ ] 入力ビューの照会ボタンは、レイヤ設定を展開して内容が長くなっても、スクロールなしで左ペイン最下部から常に操作できる。
- [ ] 1920×1080、1366×768、200%拡大で、左ペインと地図の操作が可能である。
- [ ] `prefers-reduced-motion` では縦移動アニメーションが発生しない。

## 8. 実装前・実装後の確認

実装前に、現在の `App.tsx`、`SettingsPanel.tsx`、`ResultsPanel.tsx`、`CollapsibleSidebar.tsx` の責務と状態の結び付きを確認する。特に `queryResult.status` と地図航路表示の関係を変更前にテストで固定する。

実装後は、少なくとも次を確認する。

1. 成功、一部成功、失敗、長時間待機の4経路。
2. 結果詳細が長い場合のスクロールと「再入力する」の常時到達性。
3. 再入力後に値を1項目だけ変更して再照会できること。
4. 左ペイン開閉、地図のリサイズ、地図レイヤON/OFFとの共存。
5. キーボード操作、フォーカス遷移、縮小モーション設定。
