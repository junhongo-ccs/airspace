# 改善タスク：秩父市周辺PLATEAU地物レイヤーと航路影響表示の拡張

作成日：2026年8月13日  
状態：実装完了（2026-08-17、6-10の一部を除く。ブラウザでの実描画・実画面の目視確認は未実施）  
優先度：要検討

## 1. 背景

現行のReact Viewerでは、PLATEAU秩父市2025から抽出した3次メッシュ`53397062`内の建物29件だけを、建物レイヤーとして地図に表示している。

この29件は、建物外形（LOD0）と高さ（`measuredHeight`）を持つため、航路と建物の位置関係を確認するデモとしては有効である。一方で、表示範囲は限定的であり、秩父市周辺で航路を検討する利用者が地図を移動すると、建物レイヤーをONにしても建物が表示されない区域がある。

また、道路・土砂災害・洪水浸水・土地利用は照会結果に件数だけが表示される。特に`土砂災害 1件`は、航路が土砂災害区域に入っている、または土砂災害が発生しているかのように読める。しかし現行APIは元データの分類・ポリゴンを返さないため、件数は「同じ空間IDのデータが見つかった」ことしか示しておらず、利用者の航路判断には使えない。

## 2. 目的

PLATEAU秩父市2025をデータソースとして、**秩父市周辺に限定した建物・道路・土砂災害・洪水浸水・土地利用の属性と外形を元データから再取得し、地図表示・航路影響表示用に変換・配信する仕組み**を整備する。

利用者は航路登録・照会前でも、各レイヤーをONにすることで対象範囲内の地物を地図上で確認でき、照会後は件数ではなく内容と航路との位置関係を確認できる状態を目指す。

また、データを役割の異なる二系統として扱う。建物・地形・飛行禁止区域等は**航路への影響**（回避、高度変更、安全距離の検討）であり、土砂災害・洪水浸水等は**航路活用の可能性**（災害時の状況確認、物資輸送、孤立地域支援を優先検討する根拠）である。災害リスク区域を、航路を妨げる障害物や飛行禁止区域と同じ意味で表示しない。

## 3. 完了後の利用イメージ

1. 利用者が秩父市周辺で地図を移動する。
2. 「建物」「土砂災害」「洪水浸水」「土地利用」等のレイヤーをONにする。
3. 現在の地図表示範囲にある地物の外形と内容（例：土砂災害区域の種別、土地利用区分）が表示される。
4. 航路を入力・登録すると、各地物と航路を重ねて確認できる。
5. 航路周辺を照会した場合は、建物は高さを含む判定詳細、他レイヤーは航路との水平交差・近接および内容を確認できる。

## 4. 対象範囲

### 対象

- データソース：PLATEAU秩父市2025の建物・道路・土砂災害・洪水浸水・土地利用CityGML
- 地理的範囲：秩父市周辺
- 表示属性：安定した元データID、地物種別、外形、利用可能な分類属性。建物はLOD0外形と高さ（`measuredHeight`）を含む
- 表示機能：地図の表示範囲に応じた地物レイヤーの表示・非表示
- 判定機能：建物は既存のAGLと建物高の比較ロジックを維持する。土砂災害・洪水浸水・土地利用・道路は、分類と外形が取得できたデータだけを対象に水平交差または近接を判定し、発災状況や飛行可否を示すものではないと明記する
- 表示区分：建物・地形・飛行禁止区域等は「航路への影響」、土砂災害・洪水浸水等は「航路活用の可能性」として別の見出し・色・説明で表示する。土地利用は分類ごとに、航路への影響または航路活用の可能性を補足する

### 対象外

- 全国・全自治体のPLATEAUデータ対応
- 建物用途、住所、階数、所有者などの属性追加
- 3D建物モデルの表示
- 地形レイヤーの追加
- 実運航に使う可否の最終判定

## 5. 着手前に決めること

「秩父市周辺」の境界を、次のいずれかで確定する。

- 秩父市の行政界全体
- 運用想定の中心部から指定距離（例：半径数km）
- 指定する3次メッシュの集合

あわせて、初回配信対象の推定建物件数、データ更新頻度、保存先と配信方式を決める。対象範囲が確定するまで、全量変換・配信の実装には着手しない。

## 7. 受入条件

- [ ] 指定した秩父市周辺の任意の複数地点で、建物レイヤーON/OFFにより建物外形の表示が明確に切り替わる。
- [ ] 航路登録前でも、建物レイヤーを表示できる。
- [ ] 地図を移動またはズームしても、表示済み建物が不整合なく更新される。
- [ ] 建物ID・外形・高さの対応関係を抽出時に検証し、欠測高さは高さ不明として扱われる。
- [ ] 既存の航路登録、周辺照会、150m AGL判定、DID地区レイヤーの動作を損なわない。
- [ ] 土砂災害・洪水浸水・土地利用・道路について、再取得した元データの分類・外形に基づき、内容と航路への関係が表示される。既存ボクセルの件数だけを表示する箇所はない。
- [ ] 建物等の「航路への影響」と、土砂災害・洪水浸水等の「航路活用の可能性」が、画面上で明確に区別され、災害リスク区域が飛行禁止・障害物として誤認されない。
- [ ] 1920×1080および1366×768相当で、建物表示中も地図操作が実用的な応答性を保つ。

## 8. 技術方針と留意点

- 変換処理はRenderで実行できない`SpaceInfra-cpp`に依存しない。既存のPythonによるCityGML抽出実績を発展させる。
- CityGML全体をブラウザへ一括送信しない。表示範囲単位で分割して取得・描画する。
- LOD0外形のz座標は高さ判定に使用せず、`measuredHeight`を地盤面からの相対高さとして扱う既存方針を維持する。建物以外は高さ・発災状況を推測しない。
- データ量が少ない初期範囲ではGeoJSONを候補とし、件数・応答時間・ブラウザ描画負荷の検証結果によってベクトルタイルへ移行する。
- 本機能は航路設計の補助表示であり、法令上の飛行可否を確定するものではない。

## 9. 現行実装との関係

現行の`/known_buildings`は、3次メッシュ`53397062`の29件を返す静的な参照レイヤである。本タスクでは、この固定レスポンスを秩父市周辺の表示範囲に対応した配信へ置き換える、または段階的に拡張する。

道路・土砂災害・洪水浸水・土地利用についても、現在の`ground_feature_voxel`照会結果（元データの分類・外形を失ったランダムUUID）を表示の根拠にせず、上記の変換・配信データを航路との位置関係判定と画面表示の正とする。
