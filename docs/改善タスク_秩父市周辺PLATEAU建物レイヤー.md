# 改善タスク：秩父市周辺PLATEAU建物レイヤーの拡張

作成日：2026年8月13日  
状態：未着手  
優先度：要検討

## 1. 背景

現行のReact Viewerでは、PLATEAU秩父市2025から抽出した3次メッシュ`53397062`内の建物29件だけを、建物レイヤーとして地図に表示している。

この29件は、建物外形（LOD0）と高さ（`measuredHeight`）を持つため、航路と建物の位置関係を確認するデモとしては有効である。一方で、表示範囲は限定的であり、秩父市周辺で航路を検討する利用者が地図を移動すると、建物レイヤーをONにしても建物が表示されない区域がある。

## 2. 目的

PLATEAU秩父市2025をデータソースとして、**秩父市周辺に限定した建物外形・高さデータを、地図表示用に変換・配信する仕組み**を整備する。

利用者は航路登録・照会前でも、建物レイヤーをONにすることで対象範囲内の建物を地図上で確認できる状態を目指す。

## 3. 完了後の利用イメージ

1. 利用者が秩父市周辺で地図を移動する。
2. 「建物（秩父市周辺）」レイヤーをONにする。
3. 現在の地図表示範囲にある建物外形が表示される。
4. 航路を入力・登録すると、建物外形と航路を重ねて確認できる。
5. 航路周辺を照会した場合は、従来どおり建物高を用いた判定詳細も確認できる。

## 4. 対象範囲

### 対象

- データソース：PLATEAU秩父市2025の建物CityGML
- 地理的範囲：秩父市周辺
- 表示属性：建物ID、建物外形（LOD0）、高さ（`measuredHeight`）
- 表示機能：地図の表示範囲に応じた建物レイヤーの表示・非表示
- 判定機能：既存のAGLと建物高の比較ロジックを維持し、対象データがある区域へ拡張する

### 対象外

- 全国・全自治体のPLATEAUデータ対応
- 建物用途、住所、階数、所有者などの属性追加
- 3D建物モデルの表示
- 地形、道路、洪水、土砂災害など、建物以外のレイヤー拡張
- 実運航に使う可否の最終判定

## 5. 着手前に決めること

「秩父市周辺」の境界を、次のいずれかで確定する。

- 秩父市の行政界全体
- 運用想定の中心部から指定距離（例：半径数km）
- 指定する3次メッシュの集合

あわせて、初回配信対象の推定建物件数、データ更新頻度、保存先と配信方式を決める。対象範囲が確定するまで、全量変換・配信の実装には着手しない。

## 6. 実装タスク

- [ ] 6-1. 対象境界と対象3次メッシュ群を確定し、設定ファイルとして管理する。
- [ ] 6-2. PLATEAU秩父市2025の対象CityGMLから、建物ID・LOD0外形・`measuredHeight`を抽出する変換処理を作成する。
- [ ] 6-3. 欠測高さ（例：`-9999`）を不明値として扱う検証を変換処理に組み込む。
- [ ] 6-4. 変換結果を地図配信用データとして保存する。形式はGeoJSONまたはベクトルタイルを、対象件数と表示性能に基づいて選定する。
- [ ] 6-5. BFFに、地図表示範囲（bboxまたはタイル）に対応した建物取得エンドポイントを追加する。
- [ ] 6-6. React Viewerで、地図移動・ズームに応じて必要な建物だけを取得・更新する。
- [ ] 6-7. 建物レイヤーOFF時は、建物データの描画を消去し、不要な追加取得を行わない。
- [ ] 6-8. 建物レイヤーの表記を「建物（秩父市周辺）」へ変更し、対象範囲外では表示対象外であることを画面上で分かるようにする。
- [ ] 6-9. 既存の29件限定データを、移行完了までのフォールバックとして残すか廃止するかを決める。
- [ ] 6-10. データ出典・更新日・対象範囲・加工内容を画面または付属ドキュメントへ記載する。

## 7. 受入条件

- [ ] 指定した秩父市周辺の任意の複数地点で、建物レイヤーON/OFFにより建物外形の表示が明確に切り替わる。
- [ ] 航路登録前でも、建物レイヤーを表示できる。
- [ ] 地図を移動またはズームしても、表示済み建物が不整合なく更新される。
- [ ] 建物ID・外形・高さの対応関係を抽出時に検証し、欠測高さは高さ不明として扱われる。
- [ ] 既存の航路登録、周辺照会、150m AGL判定、DID地区レイヤーの動作を損なわない。
- [ ] 1920×1080および1366×768相当で、建物表示中も地図操作が実用的な応答性を保つ。

## 8. 技術方針と留意点

- 変換処理はRenderで実行できない`SpaceInfra-cpp`に依存しない。既存のPythonによるCityGML抽出実績を発展させる。
- CityGML全体をブラウザへ一括送信しない。表示範囲単位で分割して取得・描画する。
- LOD0外形のz座標は高さ判定に使用せず、`measuredHeight`を地盤面からの相対高さとして扱う既存方針を維持する。
- データ量が少ない初期範囲ではGeoJSONを候補とし、件数・応答時間・ブラウザ描画負荷の検証結果によってベクトルタイルへ移行する。
- 本機能は航路設計の補助表示であり、法令上の飛行可否を確定するものではない。

## 9. 現行実装との関係

現行の`/known_buildings`は、3次メッシュ`53397062`の29件を返す静的な参照レイヤである。本タスクでは、この固定レスポンスを秩父市周辺の表示範囲に対応した配信へ置き換える、または段階的に拡張する。
