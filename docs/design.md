## 1. デザイン方針

本システムは、一般利用者向けWebサービスではなく、空域デジタルツインを利用した業務検討・技術検証向けのGISツールである。

一般的なカード中心のSaaSデザインは採用しない。監視システム、GISツール、分析ダッシュボードに近い高密度なUIとする。見た目のために情報量を減らしてはならない。

**判断に迷った場合の優先順位は §11 に一本化する。**本節および §4-1 に優先順位を重複して定義しない。

### 1-1. 参考とするUIの方向性

観点ごとに参照先を分ける。全体をひとつのツールに似せることは目的としない。

| 観点 | 参照先 | 何を参考にするか |
|---|---|---|
| 全体レイアウト、レイヤ制御 | QGIS、ArcGIS Pro | 左パネル＋大きな地図の構成、レイヤツリーの操作系 |
| 状態表示、警告の扱い | Grafana | 常時表示のステータス、色に依存しない状態表現 |
| 3D空域・ボクセル表現 | CesiumJS | 高度方向の可視化、視点操作 |

## 4. レイアウト

### 4-1. 基本構成

本節は §11 の優先順位「①地図面積の確保」を具体化したものである。

```text
┌──── 設定パネル ────┬────────── 地図 ──────────┐
│ API状態・評価状態    │                          │
│ 航路設定             │        （凡例：右下）     │
│ レイヤ選択           │      （スケール：左下）   │
│ 登録・照会           │  （座標／空間ID：右下帯） │
├──────────────────────┴──────────────────────────┤
│ 登録・照会結果：API応答・件数・データ時点 ［折りたたみ可］│
├─────────────────────────────────────────────────┤
│ 交差・情報不足の詳細表／CSV・GeoJSONダウンロード ［折りたたみ可］│
├─────────────────────────────────────────────────┤
│ 免責表示（固定フッター）                          │
└─────────────────────────────────────────────────┘
```

仕様書 §8 は下部を「登録・照会結果」と「交差・情報不足の詳細表／CSV・GeoJSONダウンロード」の2エリアに分けており、本書もこれに合わせる。両エリアは独立して折りたたみ可能とする。

### 4-2. 推奨寸法

| 要素 | 推奨値 | 許容範囲 |
|---|---:|---:|
| 左設定パネル幅 | 320px | 300〜340px |
| 地図 | 残り全幅 | §4-3 の最小寸法を満たすこと |
| 登録・照会結果エリア高（展開時） | 160px | 140〜176px |
| 登録・照会結果エリア高（折りたたみ時） | 32px | 固定 |
| 交差・詳細表／ダウンロードエリア高（展開時） | 160px | 140〜176px |
| 交差・詳細表／ダウンロードエリア高（折りたたみ時） | 32px | 固定 |
| 免責フッター高 | 40px | 32〜48px |

両エリアを同時に展開する場合、合計は352pxを超えないこと。導出根拠は §4-3 を参照。

### 4-3. 地図の最小寸法

**面積比では規定しない。**解像度によって面積比の意味が変わり、実現不能な要件になるためである。地図は次の最小寸法を満たすこと。

| 解像度 | 地図の最小幅 | 地図の最小高さ |
|---|---:|---:|
| 1920×1080 | 1400px | 520px |
| 1366×768 | 950px | 290px |

参考として、§4-2 の推奨値で構成した場合の実際の面積比は次のとおりである。

| 解像度 | 両エリア展開時 | 両エリア折りたたみ時 |
|---|---:|---:|
| 1920×1080 | 約 50% | 約 74% |
| 1366×768 | 約 63%（※） | 約 63% |

※ 1366×768では展開時もドロワー表示のため地図は圧縮されず、面積比は折りたたみ時と同じになる（§4-4）。

**両エリア展開時の合計高さの上限（352px）の導出**：1920×1080の有効ビューポート高912px（§2-1）から、地図の最小高さ520px（本節）とフッター40px（§4-2）を引くと352pxになる。912 − 520 − 40 = 352。§4-2の各エリアの許容範囲上限（176px×2＝352px）はこの値に一致させている。

### 4-4. 結果エリアの既定状態

「登録・照会結果」「交差・詳細表／ダウンロード」の両エリアに共通して適用する。

| 解像度 | 既定 | 展開時の挙動 |
|---|---|---|
| 1920×1080以上 | 展開 | 地図を圧縮する |
| 1366×768 | 折りたたみ | **地図の上にドロワーとして重ねる**。地図を圧縮しない |

最低解像度で両エリアを地図と縦に並べると、地図が §4-3 の最小高さを下回るため、ドロワー方式とする。1366×768では両エリアとも既定で折りたたみとし、地図の高さは496px（600−32×2−40）となり、最小高さ290pxに対して十分な余裕を確保する。

### 5-3. 地図レイヤ色

| 対象 | トークン | ブランド由来 | 塗りパターン |
|---|---|---|---|
| 航路（登録済み） | `--map-route` | `--brand-blue-dark` | 実線 4px |

| 建物 | `--map-building` | `#8A96A0`（中間グレー） | ベタ塗り |
| 地形（低） | `--map-terrain-low` | `--brand-green` | 段彩 |
| 地形（高） | `--map-terrain-high` | `#8C6239`（茶） | 段彩 |
| 情報不足・評価不能 | `--map-unknown` | `--brand-yellow` | 点ハッチ |

**重要な制約が2点ある。**

1. **`--brand-future-blue` を地図オブジェクトに使わない。**主要操作ボタンと同色になり、地図上のオーバーレイUI（レイヤ制御、凡例）と地物の区別がつかなくなる。航路には `--brand-blue-dark` を使う。
2. **黄・橙・赤は同系統で隣接すると識別が難しい。**色に加えて必ず塗りパターンを変える。上表のパターン指定は必須である。

### 5-4. 状態色

| 状態 | トークン | 値 |
|---|---|---|
| 正常・接続済み | `--status-ok` | `--brand-green` |
| 注意・未検証 | `--status-warn` | `--brand-orange` |
| エラー | `--status-error` | `--brand-red` |
| 無効・未接続 | `--status-idle` | `#8A96A0` |

### 5-5. コントラスト要件

| 対象 | 要件 |
|---|---:|
| 本文テキスト | 背景に対し 4.5:1 以上 |
| 大きい文字（16px以上・太字） | 3:1 以上 |
| UI部品の境界、アイコン | 3:1 以上 |
| 地図上のラベル | 4.5:1 以上（必要に応じハローを付す） |

**`--brand-yellow` は白背景に対し 4.5:1 を満たさない。**文字色として使用せず、塗りまたはアイコンの背景としてのみ用い、その上には `--brand-navy` の文字を載せる。同様に `--brand-cyan` も文字色に使わない。

### 5-6. 色に依存しない表現

色だけで状態を伝えない。凡例、ラベル、ツールチップ、塗りパターンのいずれかを必ず併記する。この規則は §5-3、§7、§8、§9-2 に共通して適用する。

## 9. 状態と警告

### 9-1. API接続状態

左設定パネル最上部に常時表示する。

| 状態 | 表示 | 色 |
|---|---|---|
| 接続済み | ● Connected | `--status-ok` |
| 未接続 | ● Disconnected | `--status-idle` |
| エラー | ● Error | `--status-error` |

色だけに依存せず、状態文字列を併記する。

同じ並びに、対象空間IDまたはボクセル解像度を常時表示する（仕様書 §8 必須表示項目）。この値はユーザー入力ではなく、始点・終点・AGL（§10）から算出した結果を表示する。表示形式は等幅フォント（§6-1）とする。

### 9-2. 評価状態（高度基準）

仕様書 §5-3-4 および受入基準 §11-9 に対応する。API接続状態の直下に常時表示する。

| 状態 | 表示 | 色 |
|---|---|---|
| 未検証 | ▲ 高度比較未検証／垂直判定は出力しません | `--status-warn` |
| 検証済み | ● 高度比較検証済み（許容差 ±__ m） | `--status-ok` |

**未検証の間、垂直方向の交差・離隔判定の欄を空欄にしてはならない。**「未検証」と明示し、理由へのリンクまたはツールチップを付す。空欄は「判定の結果、問題なし」と誤読される。

### 9-3. PoCデータの識別

仕様書 §6-1 に対応する。

| 箇所 | 表示 |
|---|---|
| 画面右上 | 常時バッジ：`PoC / poc-local`（`environment` の値を表示） |
| テーブル | 「区分」列に PoC／実データ を表示（§7-1） |
| 地図 | PoC由来のオブジェクトは輪郭を破線とする |

### 9-4. 安全上の注意（免責表示）

**免責文言の正文は `ドローン航路GIS-PoC_仕様書.md` §2-2 に置く。本書では文言を保持せず、仕様書の文字列をそのまま表示すること。**二重に持つと必ず表記がずれる。

表示要件は次のとおり。

- 固定フッター（高さ40px、§4-2）に常時表示する
- 通常の通知やトーストに埋没させない
- ダウンロード出力（CSV／GeoJSON）およびAPIレスポンスにも同一文字列を含める

## 10. フォームと操作

| 要素 | 仕様 |
|---|---|
| 入力欄の高さ | 32px |
| 項目間隔 | 8px |
| ボタンの高さ | 32〜36px |
| 強調色を使うボタン | 登録、照会、更新のみ |

主な入力項目は、API接続先、始点・終点、AGL、対象レイヤとする（仕様書 §7-3 Phase C手順1に対応）。対象空間IDまたはボクセル解像度はユーザー入力ではなく、始点・終点・AGLから算出して表示する値であり、§9-1で扱う。

外部状態を変える操作には、実行前に対象件数・対象レイヤを、実行後に結果件数とAPI応答時刻を明示する。

### 10-1. 空状態・エラー・処理中

仕様書 §7-3-5「取得不能、属性不足を『要確認』として表示する」に対応する。

| 状況 | 表示 |
|---|---|
| 該当0件 | 「該当するデータがありません」＋ 適用中の条件を再掲 |
| 取得失敗 | 「取得できませんでした」＋ HTTPステータス ＋ エンドポイント ＋ 再試行ボタン |
| 属性不足 | 行に「要確認」バッジ（`--status-warn`）＋ 不足している属性名 |
| 未登録（初回） | 「まだ航路が登録されていません」＋ 登録手順への導線 |
| 処理中 | 進捗バー ＋ 経過時間 ＋ 対象件数。**CityGML変換は分単位を想定し、無反応の待ち時間を作らない** |

## 11. 判断基準

デザイン上の判断に迷った場合は、次の順で優先する。**本システムにおける優先順位の定義は本節のみとする。**

1. 地図面積の確保
2. 情報密度
3. 操作効率
4. 一貫性
5. 見た目

見た目のために情報量を減らしてはならない。GISツールとしての業務効率を最優先とする。

## 12. アクセシビリティ

| 項目 | 要件 |
|---|---|
| コントラスト | §5-5 による |
| キーボード操作 | すべての操作をマウスなしで完結できる |
| フォーカス表示 | 2pxのフォーカスリング。明背景・暗背景の双方で視認できるよう、内側1px白＋外側2px `--focus-ring` の二重縁とする |
| Tab順 | 左設定パネル → 地図 → 結果エリア → フッター |
| ショートカット | 照会：`Ctrl+Enter`／レイヤパネル開閉：`Ctrl+L`／凡例開閉：`Ctrl+G`（実装時に確定） |
| 色覚特性 | 黄・橙・赤が隣接するため、塗りパターンの併用を必須とする（§5-3） |
| 画面拡大 | 200%拡大時も操作可能とする。地図の最小寸法要件は適用外とする |

## 13. カード・アイコンの利用

### 13-1. カード

使用可：設定パネル、API状態表示、評価状態表示。  
使用不可：地図全体のカード化、テーブル全体のカード化、不要なシャドウ。

カードは情報密度を下げない範囲でのみ用いる。

### 13-2. アイコン

アイコンの使用対象は、接続状態、評価状態、ダウンロード、レイヤ表示、警告に限定する。

アイコンだけで意味を伝えず、必ずラベルまたはツールチップを付与する。

## 14. Streamlit実装時の許容差

本書は将来のWeb UIも対象とするため、Streamlitでは標準機能で実現できない指定がある。次の範囲で妥協を認める。**妥協した箇所は実装時に記録し、React等へ移行する際の是正対象とする。**

| 本書の指定 | Streamlitの実情 | 許容 | 対応方法 |
|---|---|---|---|
| 左パネル幅 320px | `st.sidebar` は幅指定不可（既定 約21rem） | 300〜340pxに収まればCSS上書きで対応。困難なら既定幅を許容 | `st.markdown` によるCSS注入 |
| 入力欄の高さ 32px | 既定 38〜40px | 40pxまで許容 | CSS上書き |
| テーブル行高 32px | `st.dataframe` の行高制御は限定的 | 40pxまで許容。ただし本文12pxは維持 | `st.dataframe(row_height=...)` または HTML描画 |
| 結果エリアの下部固定 | 縦積みが基本 | `st.expander` による折りたたみで代替 | 位置固定は求めない |
| 固定フッター | 標準機能なし | CSSで `position: fixed` を注入。困難な場合はサイドバー最下部＋地図上の常時バナーで代替 | **免責表示は代替してでも必ず常時表示する（§9-4）。ここだけは妥協不可** |
| フォーカスリング | 既定スタイルあり | 既定を許容 | — |
