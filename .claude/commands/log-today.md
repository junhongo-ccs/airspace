`docs/進捗ログ.md` に本日分の作業記録を書く。

## 手順

1. `git -c core.quotepath=false status --porcelain` と `git diff` と `git log --oneline -15` で、今回のセッションの変更内容を把握する。会話の履歴からも、判断の経緯・踏んだバグ・ユーザーが決めた事項を拾う。
2. `docs/進捗ログ.md` の先頭を読み、**本日の日付の `## YYYY-MM-DD` 節が既にあるか**を確認する。
   - ある場合：その節の「実施内容」に項番を続けて追記し、「既知の問題・未解決事項」「次回タスク」を最新の状態へ更新する。
   - ない場合：ファイル先頭の `---` の直後（＝既存の最新エントリより上）に新しい節を作る。
3. **既存の記述を書き換えない。過去のエントリには一切触れない。**
4. 次の3節を必ず書く。

   - `### 実施内容`：番号付きリスト。**結果だけでなく、判断の経緯・試して駄目だった方式・踏んだバグとその原因**を書く。次のセッションの自分が同じ壁にぶつからないための記録であり、コミットログの写しではない。ユーザーが決めた割り切りは「（ユーザー決定）」と明記する。実測値（件数・バイト数・時間）は具体的な数字で書く。
   - `### 既知の問題・未解決事項`：解決しなかったこと、判明した制約、確認できていないこと。最優先のものは **【最優先・未解決】** を付けて先頭に置く。前回から解決済みの項目は落とす。
   - `### 次回タスク`：番号付きで、着手順に。

5. 関連するタスクのチェックボックス（`docs/実装タスクリスト.md` / `docs/改善タスク_*.md`）を更新し、実装場所・実測値・見送り理由を同じ行に追記する。冒頭の「状態」行も必要なら更新する。
6. 仕様に影響する変更をしていた場合は、`docs/ドローン航路GIS-PoC_仕様書.md`（および該当すれば `docs/design.md`）の版を上げ、冒頭の変更履歴テーブルに1行追加し、ステータス行を更新する。

## 注意

- 検証していないことを検証済みとして書かない。ブラウザでの実描画確認は Claude Code のブラウザ自動化では行えない（タブが `visibilityState=hidden` になるため）。確認をユーザーに依頼した場合はその旨を書く。
- 追記後、書いた内容の要点をユーザーへ3〜5行で報告する。
